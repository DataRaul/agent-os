# Aligner procedure

Run inside the coordinator for normal requests. Use a separate bounded session only for consequential ambiguity or conflicting context. Do not impose a form on the user.

Reconstruct authorized outcome and purpose from current instructions, sourced goal revisions, checkpoint and live evidence. Separate requirements, preferences, examples and assumptions. Check scope, material premises, inputs, acceptance evidence, constraints, authority, dependencies and stopping point. Complete means enough to execute the next package.

Record goal version/hash, intent provenance, criterion IDs, contribution, input identities, mandatory reasoning domains, inherited budget, next action and stop boundary. Apply canonical project mandate/coach mechanisms without duplicating domain reasoning. Use AUTO, AUTO + VERIFY, HUMAN GATE or BLOCKED. Resolve ordinary reversible choices internally. Ask only when a missing choice materially changes the result, with a prefilled interpretation and at most three questions.

Optional template: outcome; this package's deliverable; must preserve/avoid; success evidence; authority through which boundary. Prefill known answers. A handover locates evidence but does not prove freshness or completeness.

Check alignment at package selection, material discovery, review/publication and handover/resume. Preserve frozen criteria until an authorized revision changes them. Passing tests does not establish the goal. Never convert an illustrative example into a universal requirement.
